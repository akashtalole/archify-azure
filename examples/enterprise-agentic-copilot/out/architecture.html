Claims and customer operations: Copilot Studio, Power Automate, Azure AI Foundry and Microsoft Fabric

Flow

  1. 1A customer reports a claim or asks about coverage in the web chat or Teams; Copilot Studio authenticates them with Entra ID
  2. 2Uploaded photos and forms trigger the document intake flow, which extracts fields and creates the case in Dataverse
  3. 3Document intake flow → Claims case records (create case)
  4. 4Coverage and status questions are handed to the Foundry orchestrator through the API Management AI gateway, with the user's token
  5. 5API Management → Claims orchestrator (invoke)
  6. 6The orchestrator plans with the model; every prompt and response passes Content Safety
  7. 7Claims orchestrator → Fraud-signal agent (connected agent)
  8. 7Claims orchestrator → Policy agent (connected agent)
  9. 7Claims orchestrator → Action agent (connected agent)
  10. 8The policy agent grounds coverage answers in the indexed policy wording
  11. 8The fraud-signal agent asks the Fabric data agent for claim history and stream-derived signals, as the signed-in user
  12. 9Fabric data agent → OneLake lakehouse (SQL / DAX)
  13. 10The action agent calls approved tool APIs; high-impact actions go to the approval flow
  14. 11The approval flow routes payouts above the threshold to an adjuster in Teams
  15. 12Approval flow → Claims case records (record decision)
  16. 13Claims adjusters → Adjuster copilot (triage chat)
  17. 14Core claims and policy systems → Mirroring and pipelines (mirror)
  18. 14Telematics and IoT → Real-Time Intelligence (events)
